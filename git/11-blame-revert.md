# git blame과 git revert

## git blame

```bash
git blame [파일 이름]
```

- 파일의 **줄마다** 어떤 커밋에서 누가 작성했는지 보여준다.
- 각 줄 앞에 커밋 ID, 작성자, 날짜가 나온다.
- 더 자세히 보고 싶으면 그 커밋 ID로 `git show [커밋 ID]`를 친다.

```
a0211fd (chan-young 2026-10-30) def square(a):
e7baa7b (kyuri      2026-10-28)     return a*a
```

| 명령어 | 기준 | 보여주는 것 |
|---|---|---|
| `git log` | 저장소 전체 | **커밋 목록** |
| `git blame` | 파일 하나 | **줄마다** 어떤 커밋이 만들었는지 |

- 둘 다 "기록을 본다"는 점은 같지만, 보는 단위가 다르다.

## git revert

```bash
git revert [취소할 커밋 ID]
```

- 과거로 돌아가는 게 아니라, **커밋 하나의 변경을 취소하는 새 커밋**을 만든다.
- 커밋 메시지 입력 화면(vim)이 뜨면 `Revert "..."`라는 기본 메시지가 적혀 있다. 그대로 `:wq`하면 된다.
- 커밋 ID는 앞 4글자부터 되지만 보통 7글자를 쓴다. (`git hist`로 확인)

### 예시: 잘못된 square 함수를 이미 push했다

```
1 - 2 - 3 - 4 - 5(square 추가)        ← main, origin/main
```

```bash
git revert [5번 커밋 ID]
git push
```

```
1 - 2 - 3 - 4 - 5 - 6(5번 취소)       ← main, origin/main
```

- 6번 커밋은 5번에서 한 일을 되돌린 커밋이다.
- 그래서 **4번과 6번의 파일 내용은 같다.** 기록은 5번까지 그대로 남는다.

### 왜 reset을 쓰면 안 되나?

reset으로 4번으로 돌아가면

```
로컬:  1 - 2 - 3 - 4                  ← main
리모트: 1 - 2 - 3 - 4 - 5             ← origin/main
```

- 내 로컬이 리모트보다 **뒤에** 있어서 push가 거절된다.
- pull로 받아오면 5번(square)이 다시 들어와서 원래대로 돌아간다.
- force push로 밀어버리면 이미 5번을 받은 팀원들의 기록이 꼬인다.

반면 revert는 새 커밋(6번)을 **앞에 추가**하는 거라 그냥 push된다.

| | 혼자 쓰는 로컬 (push 전) | 공유된 커밋 (push 후) |
|---|---|---|
| 사용 | `reset` | `revert` |

### ⚠️ reset과 적는 ID가 반대

| 명령어 | 적는 커밋 ID |
|---|---|
| `git reset` | **이동할(남길)** 커밋 |
| `git revert` | **취소할** 커밋 |

## 여러 커밋 한 번에 revert

커밋이 `facd` → `4fa1` → `eea5` 순서로 쌓여 있을 때 (오래된 것 → 최신)

```bash
git revert facd..eea5
```

- `4fa1`, `eea5` 두 개를 취소한다.
- ⚠️ **앞에 적은 커밋(facd)은 포함되지 않는다.** "facd 다음부터 eea5까지"라는 뜻.
- 순서는 **오래된 것..최신** 순으로 적는다. 반대로 적으면 아무것도 취소되지 않는다.
- 취소한 커밋 수만큼 revert 커밋이 각각 생기고, vim 화면도 그만큼 뜬다. 매번 `:wq`하면 된다.

## 참고

- revert도 충돌이 날 수 있다. (취소하려는 부분을 이후 커밋이 또 고친 경우) 해결 방법은 merge 충돌과 같고, 취소하려면 `git revert --abort`
- `git history`는 커밋 목록을 보는 명령어가 아니다. 커밋 목록은 `git log` (또는 `git hist`)로 본다.

## 요약

| 명령어 | 하는 일 |
|---|---|
| `git blame` | 파일의 줄마다 어떤 커밋이 만들었는지 출력 |
| `git revert` | 특정 커밋의 작업을 취소하는 **새 커밋** 생성 |
| `git fetch` | upstream에서 최신 커밋을 가져오기만 함 (→ `10-pull-fetch.md`) |
