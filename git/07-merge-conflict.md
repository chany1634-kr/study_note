# merge와 conflict

## git merge

나눠서 작업한 브랜치를 하나로 합칠 때 사용한다.

```bash
git switch master       # 합쳐 받을 브랜치로 먼저 이동
git merge premium       # 현재 브랜치(master)에 premium 브랜치를 합친다
```

- merge는 **덮어쓰기가 아니라 양쪽 변경을 모두 살려서 합치는 것**이다.
- 합치면 **머지 커밋**이 새로 생기고, 부모 커밋이 2개가 된다.
- 머지 커밋 메시지 입력 화면(vim)이 뜨면 `Merge branch 'premium'`이라는 기본 메시지가 이미 적혀 있다. 그대로 쓰려면 `:wq`로 저장하고 나오면 된다.

## 3-way merge

Git은 3개의 커밋을 비교해서 자동으로 합친다.

| 이름 | 의미 |
|---|---|
| **base** | 두 브랜치가 갈라지기 전 공통 조상 커밋 |
| **master** | 현재 브랜치의 최신 커밋 |
| **premium** | 합쳐 올 브랜치의 최신 커밋 |

base와 비교해서 **누가 바꿨는지**를 보고 판단한다.

| 경우 | base | master | premium | 결과 | 이유 |
|---|---|---|---|---|---|
| 1 | A | A | B | **B** | premium만 바꿈 |
| 2 | 1 | 2 | 1 | **2** | master만 바꿈 |
| 3 | "hello" | (삭제) | "hello" | **(삭제)** | master만 바꿈 |
| 4 | "bye" | "fighting" | "please" | **CONFLICT** | 둘 다 다르게 바꿈 |

- 한쪽만 바꿨다 → 바꾼 쪽을 따른다
- 둘 다 같은 곳을 다르게 바꿨다 → Git이 판단할 수 없어서 **충돌(conflict)**

## conflict가 나면

`CONFLICT`라는 문구가 뜨고, 충돌난 파일에 이런 표시가 생긴다.

```
<<<<<<< HEAD
fighting
=======
please
>>>>>>> premium
```

- `<<<<<<< HEAD` ~ `=======` : **위 = 내 것** (현재 브랜치 master의 내용)
- `=======` ~ `>>>>>>>` : **아래 = 상대 것** (합쳐 올 쪽의 내용)
- `>>>>>>>` 뒤에는 상대 쪽 이름이 붙는다. 브랜치 이름(`premium`, `origin/master`)이나 커밋 메시지가 올 수 있다.

충돌난 파일 목록은 `git status`로 확인할 수 있다.

### 실제 코드 예시

같은 자리에 서로 다른 함수를 추가해서 충돌이 난 경우

```
<<<<<<< HEAD
def get_Median(a, b):
    return (a+b)/2
=======
def get_Remainder(a, b):
    return a//b
>>>>>>> Add get_Remainder function
```

둘 다 필요하면 표시만 지우고 둘 다 남긴다.

```python
def get_Median(a, b):
    return (a+b)/2

def get_Remainder(a, b):
    return a//b
```

- 꼭 한쪽만 고르는 게 아니다. **위만, 아래만, 둘 다, 새로 작성** 모두 가능하다.

## 해결 방법 1: 직접 고치고 merge 완료하기

꼭 지금 merge를 끝내야 하는 상황일 때.

1. 충돌난 파일을 에디터(Sublime Text, VS Code 등)로 연다.
2. 원하는 결과 모습으로 코드를 수정한다.
3. `<<<<<<<`, `=======`, `>>>>>>>` 표시를 **꼭 지운다.**
   - ⚠️ 표시를 안 지우고 커밋하는 실수가 꽤 많다. 그대로 커밋돼서 코드가 깨진다.
4. `git add [파일 이름]` → 이 상태를 **resolved(해결됨)**라고 한다.
5. 모든 충돌을 해결했으면 `git commit`

충돌난 파일이 여러 개일 때는

- 파일 하나씩 해결하고 `git add [파일 이름]`으로 하나씩 올리거나 (중간중간 `git status`로 확인)
- 전부 해결한 뒤 `git add .`로 한 번에 올리고

커밋하면 된다.

## 해결 방법 2: merge 취소하기

충돌이 너무 많거나, 나중에 merge해도 되는 상황일 때.

```bash
git merge --abort
```

- merge하기 **전 상태로 완전히 돌아간다.** (abort = 중단하다, 취소하다)

### Q. 충돌 3개 중 1개만 고쳐서 add하고, 나머지 2개만 되돌릴 수 있나?

**안 된다.** `--abort`는 merge 자체를 통째로 취소하는 명령어라서, 이미 고치고 add한 1개까지 전부 merge 전으로 돌아간다.

→ merge를 끝내려면 **전부 해결**하고, 아니면 **전부 취소**해야 한다.

## 참고

- 충돌은 협업할 때만 나는 게 아니다. 혼자서도 브랜치끼리 merge, rebase, stash pop을 할 때 같은 줄을 다르게 바꿨으면 충돌이 난다.
- `commit` 자체로는 충돌이 나지 않는다. 충돌은 항상 "합칠 때" 생긴다.
